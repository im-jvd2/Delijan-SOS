# الزامات فنی میزبانی (Hosting Requirements)

این سند **چک‌لیست خرید** است. هر سرویسی که این الزام‌ها را نداشته باشد، حذف می‌شود.

---

## ۱. چرا هاست برای این پروژه حیاتی است

سایت ما یک سایت **اضطراری** است: کاربر در حاشیهٔ جاده، با اینترنت موبایل ضعیف، منتظر است. هر ۱۰۰ میلی‌ثانیه تأخیر = از دست رفتن تماس. ضمناً **TTFB مستقیماً بخشی از LCP است** و LCP یک سیگنال رتبه‌بندی گوگل است.

نتیجه: هاست، یک خرید «سئویی» است نه یک خرید «فنی».

---

## ۲. الزامات اجباری (Must-Have)

| # | الزام | حداقل | دلیل |
|---|---|---|---|
| H1 | **موقعیت دیتاسنتر** | ایران | پینگ پایین برای مخاطب ۱۰۰٪ داخلی |
| H2 | **وب‌سرور** | LiteSpeed (یا Nginx با FastCGI Cache) | کش صفحه در سطح سرور، بدون پلاگین سنگین |
| H3 | **نسخهٔ PHP** | ۸.۲ یا ۸.۳ (قابل انتخاب) | وردپرس + المنتور پرو؛ PHP ۷.۴ منسوخ و ناامن است |
| H4 | **پایگاه داده** | MySQL 8.0+ یا MariaDB 10.6+ | سازگاری و کارایی |
| H5 | **حافظهٔ ذخیره‌سازی** | NVMe SSD، حداقل ۵ گیگابایت | سرعت I/O |
| H6 | **حافظهٔ RAM اختصاصی** | ≥ ۲ گیگابایت | ویرایشگر المنتور پرو رم زیادی مصرف می‌کند |
| H7 | **پردازنده** | ≥ ۲ هسته | پردازش همزمان کش و PHP |
| H8 | **حداقل `memory_limit`** | ۵۱۲M (ترجیحاً ۷۶۸M) | خطای «memory exhausted» در المنتور |
| H9 | **`max_execution_time`** | ≥ ۳۰۰ ثانیه | برای ایمپورت قالب و به‌روزرسانی |
| H10 | **SSL رایگان + تجدید خودکار** | Let's Encrypt | الزام HTTPS |
| H11 | **بکاپ خودکار** | روزانه، با امکان بازیابی نقطه‌ای | الزام |
| H12 | **دسترسی SSH** | دارد | WP-CLI، دیباگ، مدیریت |
| H13 | **کنترل پنل** | cPanel یا DirectAdmin | استاندارد بودن |
| H14 | **محافظت امنیتی** | Imunify360 یا معادل + Anti-DDoS | سایت‌های وردپرسی هدف دائمی هستند |
| H15 | **پشتیبانی** | ۲۴/۷، تیکت + تلفن، پاسخ < ۳۰ دقیقه | سایت شبانه‌روزی = پشتیبانی شبانه‌روزی |
| H16 | **تضمین بازگشت وجه** | ≥ ۷ روز | امکان تست واقعی |
| H17 | **پهنای باند** | نامحدود یا ≥ ۵۰۰ گیگابایت/ماه | — |
| H18 | **تعداد ادان/پارک دامنه** | ≥ ۲ | برای دامنهٔ دوم و `staging` |

## ۴. موارد ردکننده (Deal-Breakers)

اگر سرویسی هر یک از این‌ها را داشت، **حذف** می‌شود:

- ❌ دیتاسنتر فقط خارج از کشور (بدون گزینهٔ ایران)
- ❌ وب‌سرور Apache بدون LiteSpeed/Nginx و بدون کش
- ❌ عدم پشتیبانی از PHP 8.2+
- ❌ بکاپ فقط هفتگی یا بدون امکان بازیابی توسط ما
- ❌ نبود دسترسی SSH
- ❌ محدودیت `memory_limit` زیر ۲۵۶M و غیرقابل تغییر
- ❌ عدم وجود گارانتی بازگشت وجه
- ❌ گزارش‌های متعدد کاربران از دان‌تایم طولانی

---

## ۵. اندازه‌گیری مورد نیاز سایت

### برآورد منابع

| قلم | برآورد |
|---|---|
| تعداد صفحات | ~۶۰ تا ۸۰ |
| تعداد بازدید روزانه (سال اول) | ۱۰۰ تا ۱٬۰۰۰ |
| حجم محتوا | < ۱ گیگابایت (با تصاویر بهینه) |
| پهنای باند ماهانه | < ۵۰ گیگابایت (با کش و WebP) |
| بار همزمان اوج | ≤ ۲۰ کاربر |

**نتیجه:** یک **هاست وردپرس متوسط با LiteSpeed** کاملاً کافی است. نیازی به سرور اختصاصی یا VPS در سال اول نیست.

### نقطهٔ ارتقا
اگر بازدید روزانه از ۵٬۰۰۰ گذشت یا LCP با کش فعال هم بالای ۲.۵ ثانیه ماند → مهاجرت به **هاست ابری/VPS با منابع ایزوله**.

## ۶. پیکربندی بهینهٔ PHP (برای اعمال پس از خرید)

```ini
memory_limit = 512M
upload_max_filesize = 64M
post_max_size = 64M
max_execution_time = 300
max_input_vars = 3000
max_input_time = 300
opcache.enable = 1
opcache.memory_consumption = 256
opcache.max_accelerated_files = 20000
opcache.validate_timestamps = 1
opcache.revalidate_freq = 60
expose_php = Off
```

> ⚠ `max_input_vars = 3000` برای المنتور ضروری است؛ مقدار پیش‌فرض ۱۰۰۰ باعث **ذخیره‌نشدن بخشی از تنظیمات صفحه** می‌شود (باگ رایج و گیج‌کننده).
