# امنیت، بکاپ و مدیریت اعتبارنامه‌ها

> **چرا برای این پروژه حیاتی است:** سایت‌های «امداد خودرو» ترافیک اضطراری و اعتماد بالایی دارند. یک هک موفق = ریدایرکت کاربر به سایت شرط‌بندی = **حذف از گوگل** و از دست رفتن کل سرمایهٔ سئو.

---

## ۱. تهدیدهای واقعی

| تهدید | احتمال | اثر |
|---|---|---|
| حملهٔ Brute-force به `wp-login.php` | بسیار بالا | دسترسی کامل |
| آسیب‌پذیری پلاگین به‌روز نشده | بالا | تزریق کد |
| پلاگین/قالب nulled | بالا | بدافزار از روز اول |
| رمز عبور ضعیف کنترل پنل | متوسط | دسترسی کامل به سرور |
| فیشینگ ایمیل کارفرما | متوسط | سرقت دامنه |
| انقضای دامنه/هاست | متوسط | از دست رفتن کامل سایت |

---

## ۲. کنترل‌های اجباری

### ۲.۱ سطح وردپرس
- [ ] نام کاربری مدیر ≠ `admin`
- [ ] رمز عبور ≥ ۲۴ کاراکتر، تصادفی، ساخته‌شده با Password Manager
- [ ] **2FA فعال** برای همهٔ کاربران (TOTP)
- [ ] `DISALLOW_FILE_EDIT = true` در `wp-config.php`
- [ ] محدودسازی تلاش ورود (پلاگین یا `.htaccess`)
- [ ] تغییر آدرس ورود (اختیاری، با احتیاط — ممکن است خودمان قفل شویم)
- [ ] غیرفعال‌سازی **XML-RPC** اگر استفاده نمی‌شود:
  ```apache
  <Files xmlrpc.php>
    Require all denied
  </Files>
  ```
- [ ] مسدودسازی شمارش کاربران از REST API:
  ```
  /?rest_route=/wp/v2/users  → مسدود
  ```
- [ ] حذف نسخهٔ وردپرس از هدرها (`remove_action('wp_head','wp_generator')`)
- [ ] به‌روزرسانی خودکار امنیتی فعال (`WP_AUTO_UPDATE_CORE = 'minor'`)

### ۲.۲ سطح سرور
- [ ] مجوز فایل‌ها: پوشه `755`، فایل `644`، `wp-config.php` `600`
- [ ] ModSecurity فعال
- [ ] Imunify360 (یا معادل) فعال و به‌روز
- [ ] SSH فقط با کلید (نه رمز عبور)
- [ ] تغییر پورت پیش‌فرض SSH (اختیاری)
- [ ] Fail2Ban یا معادل
- [ ] HSTS پس از پایداری (فایل `../01-domain/03-dns-and-ssl.md`)
- [ ] هدرهای امنیتی پایه (فایل `DOM-03` بخش ۳.۳)

### ۲.۳ سطح دامنه و ایمیل
- [ ] 2FA روی پنل ایرنیک
- [ ] 2FA روی پنل هاستینگ
- [ ] 2FA روی ایمیل کارفرما
- [ ] ⛔ ارسال ایمیل وردپرس غیرفعال (`pre_wp_mail → false`) — ایمیل سازمانی نداریم (D-018)
- [ ] آگاهی کارفرما از فیشینگ: **ایرنیک هرگز رمز عبور را با ایمیل نمی‌پرسد**

---

## ۳. پلاگین امنیتی — چه زمانی؟

| وضعیت سایت | توصیه |
|---|---|
| تازه لانچ، ترافیک کم | کنترل‌های بخش ۲ کافی است. **پلاگین سنگین امنیت نصب نکنید.** |
| هدف حملات مکرر قرار گرفت | `Limit Login Attempts Reloaded` (سبک) |
| نیاز به فایروال سطح اپلیکیشن | `WP Cerber` یا `Wordfence` (سنگین‌تر — فقط در صورت نیاز) |

> ⚠ **تداخل:** LiteSpeed Cache + Wordfence + پلاگین بهینه‌ساز دیتابیس هم‌زمان = منبع رایج کندی و خطا. یکی را انتخاب کنید.

## ۴. بکاپ

### ۴.۱ استراتژی ۳-۲-۱
- **۳** نسخه از داده
- **۲** رسانه/مکان متفاوت
- **۱** نسخه خارج از سرور (و ترجیحاً خارج از کشور)

### ۴.۲ زمان‌بندی
| قلم | فراوانی | نگه‌داری |
|---|---|---|
| دیتابیس | روزانه | ۱۴ نسخه |
| فایل‌ها (`wp-content` + هسته) | هفتگی | ۴ نسخه |
| بکاپ دستی | پیش از هر تغییر بزرگ | تا ۹۰ روز |
| بکاپ خارج از سرور | روزانه (همگام) | ۳۰ روز |

### ۴.۳ مقصدها
| مقصد | وضعیت |
|---|---|
| فضای ابری ایرانی (Object Storage) | ✅ اصلی |
| فضای ابری خارجی (Google Drive/Dropbox) | ✅ ثانویه (در صورت دسترسی) |
| دانلود روی دستگاه محلی | ✅ ماهانه |
| فقط روی خود هاست | ❌ **غیرقابل قبول** |

### ۴.۴ تست بازیابی (اجباری)
- [ ] هر ۳ ماه یکبار، بازیابی کامل روی محیط staging
- [ ] تأیید: سایت بالا می‌آید، محتوا کامل است، پرمالینک‌ها درست‌اند
- [ ] ثبت نتیجه در لاگ با تاریخ

> 🚨 **بکاپ تست‌نشده = بکاپ نیست.**

### ۴.۵ اقلامی که باید در بکاپ باشند
```
✅ کل پوشهٔ public_html (یا حداقل wp-content + wp-config.php)
✅ دامپ کامل دیتابیس
✅ فایل .htaccess
✅ تنظیمات DNS (اسکرین‌شات یا export)
✅ فهرست پلاگین‌ها و نسخه‌ها (wp plugin list)
✅ قالب‌های المنتور (export JSON)
✅ کلیدهای لایسنس
```

## ۵. مدیریت اعتبارنامه‌ها (Vault)

### ۵.۱ ساختار پیشنهادی در Bitwarden/Vaultwarden
```
📁 Delijan-SOS
├── 📁 دامنه
│   ├── ایرنیک (nic.ir)
│   └── نمایندهٔ دامنه (در صورت وجود)
├── 📁 میزبانی
│   ├── cPanel
│   ├── SSH Key
│   ├── MySQL
│   └── FTP/SFTP
├── 📁 وردپرس
│   ├── مدیر پیشخوان
│   └── ⛔ ایمیل سازمانی ساخته نشد (D-018)
├── 📁 لایسنس‌ها
│   └── Elementor Pro
├── 📁 سرویس‌های جانبی
│   ├── Google Search Console
│   ├── Google Analytics
│   ├── CDN
│   └── UptimeRobot
└── 📝 یادداشت‌ها
    ├── ساختار DNS
    ├── تاریخ تمدیدها
    └── صورت‌جلسهٔ تحویل
```

### ۵.۲ قوانین
1. **هرگز** رمز در چت، ایمیل، پیام‌رسان، فایل متنی یا اسکرین‌شات ارسال نشود.
2. اشتراک‌گذاری فقط از طریق قابلیت «Send» با انقضا و محدودیت دسترسی.
3. **مالکیت Vault از روز اول به نام کارفرما** — ما فقط عضو هستیم.
4. در پایان پروژه، کارفرما همهٔ رمزها را **تغییر** می‌دهد.
5. هر تغییر رمز در لاگ ثبت شود.

## ۶. برنامهٔ پاسخ به حادثه

### اگر سایت هک شد:
1. **حفظ شواهد:** قبل از پاک‌کردن، بکاپ بگیرید (برای تحلیل)
2. **قطع دسترسی:** سایت را به حالت تعمیر ببرید؛ رمز همهٔ کاربران تغییر کند
3. **بازیابی از بکاپ سالم** (آخرین بکاپ پیش از آلودگی)
4. **به‌روزرسانی کامل** هسته، قالب، پلاگین‌ها
5. **اسکن:** Imunify360 + اسکن دستی `wp-content/uploads` برای فایل‌های PHP
6. **بررسی کاربران:** کاربر ناشناس اضافه نشده باشد
7. **درخواست بازبینی در Search Console** (اگر Manual Action خورد)
8. **ثبت حادثه** در لاگ با علت ریشه‌ای

### اگر سایت دان شد:
1. بررسی UptimeRobot → چه زمانی
2. بررسی لاگ هاستینگ / تیکت به پشتیبانی
3. اگر حملهٔ DDoS → فعال‌سازی محافظت هاستینگ/CDN
4. ثبت و تحلیل
